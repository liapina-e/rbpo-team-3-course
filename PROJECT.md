# Паспорт проекта

## Общие сведения

**Название команды:** DevDivas  
**Название продукта:** TempShare  
**Коды участников:** `M1`, `M2`, `M3`, `M4`  
**Статус ранней калибровки:** `черновик`

## 1. Назначение

TempShare — серверное приложение с HTTP API для передачи файлов выбранным получателям на ограниченный срок. Владелец загружает файл и выдаёт именные разрешения на его скачивание конкретным пользователям, указывая момент окончания срока действия; по истечении срока доступ прекращается сам, а до его наступления владелец может отозвать разрешение досрочно.

Результат получают две стороны: владелец файла, которому нужно передать материал ограниченному кругу лиц и сохранить контроль над сроком передачи, и получатель, которому нужен доступ к файлу в течение этого срока.

Собственная предметная логика приложения — управление разрешениями: связывание файла, получателя, срока и состояния разрешения, вычисление действующего разрешения на момент обращения и проверка права доступа при каждой выдаче содержимого.

## 2. Граница продукта

**В продукт входит:**

- серверное приложение и его HTTP API;
- предметная логика разрешений: выдача, срок действия, отзыв, определение действующего разрешения;
- проверка права доступа при каждом обращении к содержимому файла;
- хранилище метаданных (файлы, разрешения, учётные записи) и его схема;
- хранилище содержимого загруженных файлов;
- механизм регистрации и аутентификации пользователей и его настройка;
- конфигурация локального запуска приложения и хранилищ.

**Внешнее окружение и внешние системы:**

- HTTP-клиент пользователя (браузер, `curl`, Postman) вне ответственности команды;
- операционная система, файловая система и системные часы хост-машины;
- среда выполнения .NET и контейнерная среда, если она используется при запуске;
- сеть между клиентом и сервером.

Внешние сервисы, необходимые для работы основных сценариев, не используются.

**Команда сознательно не реализует:**

- веб-интерфейс и мобильное приложение, взаимодействие с продуктом происходит через HTTP API;
- уведомления получателей и владельца (почта, push, мессенджеры), в том числе об истечении срока;
- антивирусную проверку и любой анализ содержимого загружаемых файлов;
- предпросмотр, редактирование и конвертацию файлов;
- шифрование содержимого на стороне клиента;
- публичные ссылки для доступа без указания конкретного получателя;
- версионирование файлов и совместное редактирование;
- восстановление пароля, вход через внешних провайдеров и подтверждение адреса почты;
- полнотекстовый поиск, аналитику, отчётность, тарифы и квоты;
- перенос уже существующих разрешений между пользователями и делегирование прав владельца.

## 3. Пользователи и доступные действия

Полномочия определяются не глобальной ролью, а отношением пользователя к конкретному файлу: один и тот же пользователь является владельцем загруженных им файлов и одновременно получателем файлов, разрешения на которые выданы ему другими.

| Пользователь или роль | Кто это | Что может делать | Что ему недоступно |
| --- | --- | --- | --- |
| Владелец файла | Аутентифицированный пользователь, загрузивший файл | Загрузить файл; просмотреть перечень своих файлов и их метаданные; выдать именное разрешение выбранному пользователю с указанием срока; просмотреть перечень получателей своего файла и состояние их разрешений; отозвать ранее выданное разрешение; скачать собственный файл | Выдавать и отзывать разрешения на чужие файлы; получать содержимое и метаданные чужих файлов без действующего разрешения; просматривать перечни файлов и получателей других владельцев; изменять момент окончания срока задним числом для уже завершившегося разрешения |
| Получатель | Аутентифицированный пользователь, которому владелец выдал именное разрешение на конкретный файл | Просмотреть перечень файлов, доступных лично ему; просмотреть метаданные такого файла и срок своего разрешения; скачать содержимое файла, пока разрешение действует | Выдавать разрешения на этот файл другим пользователям; отзывать и продлевать собственное разрешение; изменять или удалять файл; скачивать содержимое после истечения срока или отзыва; видеть других получателей этого файла и их разрешения |
| Неаутентифицированный посетитель | Обращение к API без подтверждённой аутентификации | Зарегистрироваться, выполнить вход | Любые операции с файлами и разрешениями: загрузка, скачивание, выдача и отзыв разрешений, просмотр метаданных, перечней файлов и перечней получателей |

## 4. Сквозные сценарии

### Сценарий 1. Поделиться файлом на ограниченный срок

- **Участники:** владелец файла
- **Начальное условие:** пользователь аутентифицирован; файл ещё не размещён в продукте; получатели известны владельцу как пользователи продукта
- **Основные действия:** владелец загружает файл; продукт сохраняет содержимое и метаданные и закрепляет владельца за файлом; владелец выбирает одного или нескольких пользователей и выдаёт каждому именное разрешение, указывая момент окончания срока действия
- **Результат:** файл размещён в продукте, и выбранные пользователи получают возможность скачать его до наступления указанного момента; остальные пользователи такой возможности не получают
- **Какие данные или состояние изменяются:** создаются запись файла, его метаданные и сохранённое содержимое; создаются записи разрешений со связью «файл — получатель», моментом окончания срока и состоянием «действует»

### Сценарий 2. Получить файл по действующему разрешению и потерять доступ по истечении срока

- **Участники:** получатель, владелец файла
- **Начальное условие:** пользователь аутентифицирован; на файл выдано именное разрешение этому пользователю; момент окончания срока не наступил, разрешение не отозвано
- **Основные действия:** получатель запрашивает перечень доступных ему файлов, выбирает нужный и запрашивает его содержимое; продукт определяет действующее разрешение для пары «пользователь — файл» и выдаёт содержимое; после наступления момента окончания срока получатель повторяет запрос; продукт определяет, что действующего разрешения для этой пары больше нет, и отказывает в операции, не передавая содержимое
- **Результат:** до наступления указанного момента получатель получает содержимое файла; после получает отказ, причём без каких-либо действий со стороны владельца
- **Какие данные или состояние изменяются:** содержимое файла и записи разрешений не изменяются; изменяется результат определения действующего разрешения — файл перестаёт входить в перечень доступных получателю, а его обращения перестают приводить к выдаче содержимого; фиксируется факт обращения к файлу

### Сценарий 3. Досрочно прекратить доступ

- **Участники:** владелец файла, ранее получивший доступ получатель
- **Начальное условие:** пользователь аутентифицирован и является владельцем файла; у файла есть не менее одного действующего разрешения
- **Основные действия:** владелец просматривает перечень получателей своего файла и состояние их разрешений; выбирает получателя и отзывает его разрешение; продукт переводит разрешение в состояние «отозвано»
- **Результат:** выбранный получатель теряет возможность скачать файл начиная со следующего обращения; разрешения остальных получателей того же файла продолжают действовать
- **Какие данные или состояние изменяются:** состояние выбранного разрешения меняется на «отозвано»; состав и состояние остальных разрешений файла, а также содержимое файла не изменяются

## 5. Значимые данные и другие объекты

| Данные или объект | Для кого имеют значение | Последствия раскрытия | Последствия неправильного изменения, удаления или недоступности |
| --- | --- | --- | --- |
| Содержимое загруженного файла | Владелец файла и выбранные им получатели | Посторонний получает материал, который владелец передавал ограниченному кругу лиц и на ограниченный срок; вернуть переданное содержимое невозможно | Изменение означает, что получатель скачивает не тот материал, который передавал владелец, и не может этого заметить; удаление или недоступность срывает передачу в пределах срока, после истечения которого доступ уже не восстановить |
| Разрешение: получатель, момент окончания срока, состояние | Владелец файла и получатель | Раскрытие сведений о том, кому и до какого момента выдан доступ, сообщает постороннему о круге получателей файла | Добавление или изменение разрешения даёт доступ к файлу лицу, которому владелец его не предоставлял; сдвиг момента окончания срока продлевает доступ сверх решения владельца; потеря состояния «отозвано» возвращает доступ тому, у кого он был прекращён; недоступность записей останавливает и выдачу файлов, и отзыв |
| Метаданные файла и перечень его получателей | Владелец файла | Имя файла, его размер и перечень получателей раскрывают, чем и с кем делится владелец, даже если содержимое остаётся недоступным | Подмена метаданных вводит получателя в заблуждение относительно того, какой файл он скачивает; утрата связи файла с владельцем лишает его возможности управлять разрешениями на собственный файл |
| Учётные данные пользователя | Все пользователи продукта | Раскрытие позволяет постороннему действовать от имени пользователя: скачивать доступные ему файлы и распоряжаться его собственными | Изменение или удаление лишает пользователя доступа к продукту, а владельца — возможности отозвать ранее выданные разрешения на свои файлы |

## 6. Компоненты и внешние взаимодействия

Предполагаемые части продукта:

- **Серверное приложение (HTTP API)** — принимает запросы, выполняет аутентификацию, проверяет права доступа, реализует предметную логику разрешений.
- **База данных** — хранит учётные записи, записи файлов с метаданными и записи разрешений.
- **Хранилище содержимого файлов** — каталог файловой системы, доступный серверному приложению; записи базы данных ссылаются на сохранённые объекты.
- **HTTP-клиент** — внешний по отношению к продукту; на этапе курса это `curl`, Postman или браузер.

Основные взаимодействия и передаваемые данные:

- клиент → серверное приложение: подтверждение аутентификации, содержимое и имя загружаемого файла, идентификатор файла, идентификатор получателя, момент окончания срока разрешения;
- серверное приложение → клиент: перечни файлов, метаданные, состояния разрешений, содержимое файла либо отказ в операции;
- серверное приложение ↔ база данных: чтение и изменение учётных записей, записей файлов и разрешений;
- серверное приложение ↔ хранилище содержимого: запись объекта при загрузке, чтение объекта при выдаче содержимого;
- серверное приложение ← системные часы хост-машины: текущий момент времени, с которым сравнивается момент окончания срока разрешения.

Отдельной схемы на этом этапе нет; архитектурный вид будет построен позднее.

## 8. Минимальное функциональное ядро

**Обязательные функции:**

- регистрация и вход пользователя, аутентификация последующих запросов и выполнение операций от его имени;
- отказ в операциях с файлами и разрешениями для запросов без подтверждённой аутентификации;
- загрузка файла с сохранением содержимого и метаданных и закреплением владельца;
- выдача владельцем именного разрешения выбранному пользователю с указанием момента окончания срока;
- отзыв владельцем ранее выданного разрешения;
- определение действующего разрешения и выдача содержимого файла только при его наличии;
- прекращение доступа при наступлении момента окончания срока без действий владельца;
- просмотр владельцем перечня своих файлов и получателей каждого файла с состоянием их разрешений;
- просмотр получателем перечня доступных ему файлов и срока своего разрешения.

**Функции, которые можно исключить при нехватке времени:**

- удаление файла владельцем;
- продление срока уже выданного разрешения;
- массовая выдача разрешений нескольким получателям одним запросом;
- фиксация и просмотр сведений об обращениях к файлу;
- ограничение размера и типа загружаемого файла сверх минимально необходимого;
- постраничная выдача и сортировка перечней.

После удаления необязательных функций сохраняются: собственная серверная логика разрешений, три основных сценария, различие полномочий владельца, получателя и неаутентифицированного посетителя, значимые данные и изменение состояния.

## 9. Стек и путь к первой работающей версии

**Основные технологии:** C# / .NET 8, ASP.NET Core Web API, Entity Framework Core, PostgreSQL, локальная файловая система для содержимого файлов, Swagger UI для проверки, Docker Compose для запуска СУБД.

**Технологии, новые для команды:** Quartz.NET, JWT-аутентификация, потоковая загрузка и отдача файлов через IFormFile / FileStreamResult

**Внешние сервисы, необходимые для запуска:** внешние сервисы не требуются. PostgreSQL поднимается локально в контейнере, содержимое файлов хранится в локальном каталоге.

**Как основные сценарии будут запускаться и проверяться при недоступности внешних сервисов:** все компоненты запускаются локально, сетевой доступ за пределы среды запуска не требуется. При недоступности контейнера с PostgreSQL предусматривается запуск на локальном экземпляре СУБД с той же строкой подключения; для автоматических проверок допускается провайдер EF Core в памяти. Срок действия разрешения задаётся явным значением, поэтому истечение доступа проверяется без ожидания реального времени.

**Что команда реализует первым, чтобы получить запускаемую версию:** запускаемое Web API с подключением к PostgreSQL, регистрацией и входом пользователя, загрузкой файла владельцем и скачиванием собственного файла. Это даёт локально запускаемую основу с проверяемым HTTP-запросом, поверх которой добавляются разрешения, сроки и отзыв.
