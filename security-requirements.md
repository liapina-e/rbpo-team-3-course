# Требования безопасности

| ID | Требование | Критерий приёмки | Связанные T / D (позднее) |
| --- | --- | --- | --- |
| SR-01 | Система выдаёт содержимое файла только его владельцу и получателю, у которого есть действующее разрешение на этот файл (срок не истёк, разрешение не отозвано). Знание идентификатора файла само по себе доступа не даёт. Нарушение раскрывает материал, который владелец передавал ограниченному кругу лиц на ограниченный срок, и вернуть его невозможно (`PROJECT.md`, раздел 5). ASVS: `v5.0.0-8.2.2`. | При запросе содержимого файла владельца A пользователем C без разрешения или запросом без аутентификации действие отклоняется, содержимое не передаётся. При запросе получателя B после наступления момента окончания срока или после отзыва разрешения действие отклоняется, содержимое не передаётся. Отказ наступает уже при первом запросе после окончания срока, без запуска каких-либо фоновых задач: при разрешении до 12:00:00 запрос в 11:59:59 получает содержимое, запрос в 12:00:00 получает отказ, и файл отсутствует в перечне доступных получателю. Если получателю B на файл выдано несколько разрешений, после отзыва у B не остаётся ни одного действующего разрешения на этот файл, и его запрос отклоняется. Получатель B с действующим разрешением и владелец A получают содержимое файла. | T-01, T-02, T-06 |
| SR-02 | Система допускает выдачу, отзыв и продление разрешений на файл только его владельцем. Нарушение даёт доступ лицу, которому владелец его не предоставлял, продлевает доступ сверх решения владельца или возвращает доступ после отзыва (`PROJECT.md`, раздел 5). | При попытке получателя B выдать разрешение на файл владельца A пользователю C или продлить собственное разрешение действие отклоняется, набор разрешений файла и их сроки остаются прежними. При попытке пользователя C отозвать разрешение получателя B на файл A действие отклоняется, разрешение B продолжает действовать. Владелец A может выдать разрешение пользователю C и отозвать его. | T-03 |
| SR-03 | Система показывает перечень получателей файла и состояние их разрешений только владельцу файла, а метаданные файла — владельцу и получателю с действующим разрешением. Нарушение раскрывает, чем и с кем делится владелец, даже если содержимое остаётся недоступным (`PROJECT.md`, раздел 5). | При запросе перечня получателей файла владельца A получателем B или пользователем C действие отклоняется, сведения о получателях и их разрешениях не передаются. При запросе метаданных файла A пользователем C без разрешения действие отклоняется, имя и размер файла не передаются. Владелец A получает перечень получателей своего файла с состоянием их разрешений; получатель B с действующим разрешением получает метаданные файла. | T-07 |
| SR-04 | Система выполняет операцию от имени пользователя, подлинность которого подтверждена при входе, и только его. Пользователь не определяется по значениям в теле или параметрах запроса, а подтверждение аутентификации, которое система не выдавала, изменённое или с истекшим сроком, отклоняется. Нарушение позволяет постороннему скачивать файлы другого пользователя и распоряжаться разрешениями на его файлы (`PROJECT.md`, раздел 5, учётные данные). | Запрос с подтверждением аутентификации, подписанным не системой, изменённым после выдачи или с истекшим сроком, отклоняется, состояние файлов и разрешений не меняется. Если пользователь C указывает в запросе на загрузку или выдачу разрешения идентификатор пользователя A, этот идентификатор не учитывается: загруженный файл закрепляется за C, а выданное разрешение записывается от имени C. Пользователь A после входа выполняет операции со своими файлами. | T-03, T-04 |
| SR-05 | Система принимает момент окончания срока разрешения только с явно указанным часовым поясом или смещением от UTC и сохраняет его без сдвига. Нарушение продлевает доступ сверх решения владельца или сокращает его и срывает передачу (`PROJECT.md`, раздел 5, разрешение). | Запрос на выдачу разрешения с `expiresAt` без смещения (`2026-10-05T12:00:00`) отклоняется, разрешение не создаётся. Разрешение с `expiresAt = 2026-10-05T12:00:00+03:00` перестаёт действовать в 09:00:00 UTC, а не в 12:00:00 UTC. | T-08 |
| SR-06 | Загрузка файла не изменяет содержимое других файлов и не создаёт и не перезаписывает файлы вне каталога хранилища, независимо от имени файла в запросе. Нарушение означает, что получатель скачивает не тот материал, который передавал владелец, и не может этого заметить (`PROJECT.md`, раздел 5, содержимое файла). | При загрузке файла с именем `../../appsettings.json` файлы вне каталога хранилища остаются без изменений. При загрузке файла с именем, совпадающим с уже загруженным файлом другого владельца, получатели прежнего файла скачивают прежнее содержимое. Имя файла сохраняется в метаданных и показывается получателю. | T-05 |
| SR-07 | Учётная запись не может быть захвачена подбором пароля или по копии сохранённых учётных данных. Нарушение позволяет постороннему действовать от имени пользователя (`PROJECT.md`, раздел 5, учётные данные). | После пяти неудачных попыток входа подряд в одну учётную запись следующие попытки в течение 15 минут отклоняются, в том числе с верным паролем. Ответ на неверный логин и на неверный пароль одинаков. В сохранённых учётных данных пароль не содержится в открытом виде, и у двух пользователей с одинаковым паролем сохранённые значения различаются. | T-09 |
