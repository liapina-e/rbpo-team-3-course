# EC-02. Распоряжаться разрешениями может только владелец файла

### Свойство и механизм

- **Требуемое свойство:** выдавать, продлевать и отзывать разрешения на файл может только его владелец. Попытка получателя или постороннего отклоняется, разрешения и их сроки не меняются (SR-02, T-03, D-02).
- **Обеспечивающий механизм:** `PermissionsController.Grant` и `Revoke` берут пользователя из проверенного токена (`ClaimsPrincipalExtensions.GetUserId`) и до любого изменения возвращают `404`, если `file.OwnerId` с ним не совпадает. Продление — тот же `POST /api/files/{fileId}/permissions`. Чужой и несуществующий файл дают одинаковый ответ.
- **Версия и условия:** commit `b55ed5f`, код приложения не менялся, добавлен только файл тестов (ветка `s07-m1-ec02`). EF Core InMemory через `TempShareFactory`, без PostgreSQL и Docker.

### Проверки и результаты

Тесты — [PermissionOwnershipTests.cs](TempShare.Tests/PermissionOwnershipTests.cs).

- **Позитивная:** `Owner_CanGrantAndRevoke_OtherRecipientKeepsAccess` — alice выдаёт разрешения bob и carol, затем отзывает разрешение carol. Ожидается: выдача `200`, отзыв `204`, carol получает `404`, bob скачивает файл. Фактически: пройден.
- **Негативная:**
  - `Recipient_CannotExtendOwnPermission_ExpiryUnchanged` — получатель bob продлевает себе разрешение на 30 дней. Ожидается `404`, `ExpiresAt` прежний;
  - `Recipient_CannotGrantToThirdUser_PermissionSetUnchanged` — bob выдаёт разрешение carol на файл alice. Ожидается `404`, carol не скачивает файл, у файла одно разрешение;
  - `NonOwner_CannotRevoke_PermissionStaysActive` — carol и сам bob отзывают разрешение bob. Ожидается `404` в обоих случаях, `RevokedAt` пуст, bob скачивает файл.

  Фактически: все пройдены. Для контроля в отдельной копии проекта из обоих методов убиралось условие `file.OwnerId != userId`. Тогда все три теста падают: отзыв — `204`, выдача третьему — `200`, продление — `400` (его останавливает только проверка «получатель совпадает с вызывающим»). Позитивный тест при этом проходит. В репозиторий эта правка не вносилась.
- **Команда и результат:** `dotnet test` из корня репозитория — 14 тестов, 14 пройдено (10 существующих и 4 новых). Тесты выполнялись в среде .NET 8.0.21, сборка — .NET SDK 9.0.306 на копии без `global.json`.

### Вывод и границы

В проверенных сценариях выдача, продление и отзыв разрешений доступны только владельцу файла. Отказ не меняет разрешения, а действия владельца не затрагивают других получателей.

Вне области проверки: одновременные запросы на выдачу разрешения одной паре «файл — получатель», запуск с PostgreSQL, подлинность самого токена (SR-04). Проверка владельца находится в контроллере, а не в общем сервисе из D-02, поэтому новый маршрут работы с разрешениями должен её повторять.
